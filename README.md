## 1. Project Overview

**SignalSense AI** is a full-stack AI-powered web application built with **Python Flask** and **IBM watsonx.ai**. It provides telecommunications engineers, network professionals, researchers, and students with an intelligent platform to:

- **Analyze** signal quality parameters (SNR, BER, latency, throughput, RSSI, jitter, packet loss)
- **Detect** communication anomalies, interference, and network degradation
- **Optimize** communication reliability through AI-generated engineering recommendations
- **Predict** future signal failures before they occur using historical trend analysis

The application uses a **four-agent agentic AI architecture**, where each specialized agent is powered by the `meta-llama/llama-3-3-70b-instruct` model via the IBM watsonx.ai platform. All AI inference is routed through a central orchestrator that directs requests to the appropriate agent.

## 4. Multi-Agent Architecture

SignalSense AI implements a **multi-agent agentic AI pattern** where each agent is a specialized Python function that constructs a domain-specific prompt and calls IBM watsonx.ai for inference.

```
┌─────────────────────────────────────────────────────────┐
│                     USER BROWSER                        │
│         (Bootstrap 5 UI · Chart.js · fetch API)         │
└────────────────────────┬────────────────────────────────┘
                         │ HTTP POST (JSON)
                         ▼
┌─────────────────────────────────────────────────────────┐
│                  FLASK APPLICATION                      │
│                      app.py                             │
│                                                         │
│  /api/analysis   /api/detection                         │
│  /api/optimization  /api/predictive                     │
└────────────────────────┬────────────────────────────────┘
                         │
                         ▼
┌─────────────────────────────────────────────────────────┐
│                  ORCHESTRATOR                           │
│              orchestrator(agent_type, data)             │
│                                                         │
│   "analysis" ──► signal_analysis_agent()                │
│   "detection"──► signal_issue_detection_agent()         │
│   "insight"  ──► signal_insight_agent()                 │
│   "predictive"─► predictive_failure_agent()             │
└────────────────────────┬────────────────────────────────┘
                         │
                         ▼
┌─────────────────────────────────────────────────────────┐
│              generate_response(prompt)                  │
│         IBM watsonx.ai SDK · ModelInference             │
└────────────────────────┬────────────────────────────────┘
                         │ HTTPS API Call
                         ▼
┌─────────────────────────────────────────────────────────┐
│              IBM watsonx.ai Platform                    │
│       meta-llama/llama-3-3-70b-instruct                 │
│         Region: au-syd.ml.cloud.ibm.com                 │
└─────────────────────────────────────────────────────────┘
```

### Agent 1 – Signal Data Analysis Agent

**Function:** `signal_analysis_agent(data)`  
**Route:** `POST /api/analysis`  
**Page:** `/analysis`

Evaluates key signal quality parameters and generates a comprehensive engineering report.

**Input Parameters:**
| Parameter | Unit | Typical Range | Acceptable Threshold |
|---|---|---|---|
| SNR | dB | 0 – 50 | > 25 dB (good) |
| BER | ratio | 0 – 1 | < 1×10⁻³ |
| Latency | ms | 0 – 500 | < 50 ms (real-time) |
| Throughput | Mbps | 0 – 1000 | Application dependent |
| Packet Loss | % | 0 – 100 | < 1% |
| RSSI | dBm | -120 – 0 | > -70 dBm |
| Jitter | ms | 0 – 100 | < 10 ms (VoIP) |

**AI Output Sections:**
1. Overall Signal Quality Assessment (Excellent / Good / Fair / Poor)
2. Parameter-by-Parameter Analysis
3. Key Performance Observations
4. Communication Health Summary
5. Trends & Patterns

---

### Agent 2 – Signal Issue Detection Agent

**Function:** `signal_issue_detection_agent(data)`  
**Route:** `POST /api/detection`  
**Page:** `/detection`

Detects communication anomalies, interference sources, and signal degradation patterns.

**Detectable Issues:**
- Low SNR (< 15 dB) → noise interference
- High BER (> 1×10⁻³) → transmission errors
- High latency (> 100 ms) → network congestion
- High packet loss (> 2%) → link quality problems
- Weak RSSI (< -80 dBm) → signal attenuation
- High jitter (> 10 ms) → real-time communication disruption
- Electromagnetic interference patterns
- Network congestion signatures

**AI Output Sections:**
1. Detected Signal Issues
2. Root Cause Analysis
3. Severity Assessment (Critical / High / Medium / Low)
4. Communication Risk Indicators
5. Interference & Anomaly Patterns

---

### Agent 3 – Intelligent Insight & Recommendation Agent

**Function:** `signal_insight_agent(data)`  
**Route:** `POST /api/optimization`  
**Page:** `/optimization`

Generates actionable engineering recommendations prioritized by impact and implementation ease.

**Input Context:**
- Current signal metrics
- Network type (WiFi 802.11ac/ax, 4G LTE, 5G NR, Fiber, Microwave, Satellite, LoRa)
- Frequency band
- Deployment environment description
- Application requirements (VoIP, video, IoT, industrial)
- Known problems

**AI Output Sections:**
1. Signal Optimization Strategies
2. Noise Reduction & Interference Mitigation
3. Antenna & RF Optimization
4. Frequency & Channel Planning
5. Network Configuration Improvements
6. Equipment & Infrastructure Upgrades
7. Implementation Priority Summary (ranked action list)

---

### Agent 4 – Predictive Signal Failure Agent

**Function:** `predictive_failure_agent(data)`  
**Route:** `POST /api/predictive`  
**Page:** `/predictive`

Analyzes signal trends to forecast future failures and generate preventive maintenance schedules.

**Input Data:**
- Historical signal measurements (manual entry or CSV upload)
- Trend directions (latency, throughput, packet loss)
- Equipment age
- Environmental conditions
- Recent incidents and maintenance history

**AI Output Sections:**
1. Signal Degradation Forecast (7-day / 30-day / 90-day outlook)
2. Failure Probability Assessment (percentage estimates)
3. Risk Classification (Critical / High / Medium / Low)
4. Most Vulnerable Components & Links
5. Predicted Failure Modes
6. Preventive Maintenance Schedule (with timelines)
7. Early Warning Indicators (with alert thresholds)

---

### Agent Orchestrator

**Function:** `orchestrator(agent_type, data)`

The orchestrator is a simple routing function that maps an `agent_type` string key to the appropriate agent function. All Flask API endpoints call the orchestrator rather than individual agents directly, keeping routing logic centralized.

```python
routing_map = {
    "analysis":   signal_analysis_agent,
    "detection":  signal_issue_detection_agent,
    "insight":    signal_insight_agent,
    "predictive": predictive_failure_agent,
}
```

### Core Generate Function

All four agents call a single shared function:

```python
def generate_response(prompt: str) -> str:
    credentials = Credentials(url=WATSONX_URL, api_key=WATSONX_API_KEY)
    model = ModelInference(
        model_id="meta-llama/llama-3-3-70b-instruct",
        credentials=credentials,
        project_id=WATSONX_PROJECT_ID,
        params={
            GenParams.MAX_NEW_TOKENS: 1024,
            GenParams.TEMPERATURE: 0.7,
            GenParams.TOP_P: 0.9,
        }
    )
    return model.generate_text(prompt=prompt)
```


### Step 4 – Configure Credentials via `.env`

The app uses `python-dotenv` to load credentials from a `.env` file automatically on startup.

**Copy the template:**

```bash
# Windows
copy .env.example .env

# macOS / Linux
cp .env.example .env
```

**Edit `.env` with your real credentials:**

```env

WATSONX_PROJECT_ID=your_actual_project_id_here
WATSONX_URL=https://au-syd.ml.cloud.ibm.com
FLASK_DEBUG=true
FLASK_PORT=5000
```

> ⚠️ **Never push `.env` to GitHub** — it is already in `.gitignore`.
> ✅ **`.env.example` is safe to commit** — it has only placeholder values and documents all required variables.

## 12. CSV Upload Guide

Both the **Signal Analysis** (`/analysis`) and **Predictive Analytics** (`/predictive`) pages support CSV file uploads.

### How It Works

1. The browser reads the CSV file using the FileReader API
2. CSV text is sent as a string in the `csv_data` field of the JSON payload
3. Flask parses the CSV using Python's built-in `csv.DictReader`
4. The first 10–15 rows are summarised and appended to the AI prompt as historical context
5. IBM watsonx.ai analyses the dataset as part of the full prompt

### Accepted Column Names

```
snr, ber, latency, throughput, packet_loss, rssi, jitter, frequency_band, date
```

> Column names are case-sensitive. Extra columns are ignored.

## 15. AI Prompt Engineering

Each agent uses a carefully structured prompt with explicit formatting instructions to ensure clean, professional output from the model.

### Prompt Design Principles

1. **Role assignment** — Each prompt starts with a specific expert persona (`"You are a senior telecommunications engineer..."`)
2. **Anti-echo guards** — Explicit instructions prevent the model from repeating raw input data back
3. **No LaTeX** — Explicitly blocks `$\boxed{}` notation and math formatting
4. **Exact headings** — Each prompt specifies exact `## Section` headings the model must use
5. **Concise context** — For predictive agent, historical data is capped at 500 characters to prevent data regurgitation
6. **Prioritized output** — Agent 3 instructs the model to rank recommendations by impact

### Example Prompt Structure (Agent 1)

```
You are a senior telecommunications engineer and signal quality analyst.

IMPORTANT INSTRUCTIONS:
- Do NOT repeat or echo back the raw input data or CSV rows in your response.
- Do NOT use LaTeX, math boxes, or $\boxed{} notation.
- Write in plain professional English with clear headings and bullet points.

Signal Parameters:
- SNR: 32 dB
- BER: 0.002
...

Report Structure (use these exact headings):
## 1. Overall Signal Quality Assessment
## 2. Parameter-by-Parameter Analysis
## 3. Key Performance Observations
## 4. Communication Health Summary
## 5. Trends & Patterns
```

## 18. Troubleshooting

### Error: Model not supported

```
[watsonx.ai Error] Model 'ibm/granite-13b-instruct-v2' is not supported for this environment.
```

**Fix:** The Sydney (`au-syd`) region does not support `granite-13b-instruct-v2`. The app is already updated to use `meta-llama/llama-3-3-70b-instruct`. Ensure your `app.py` has:

```python
model_id="meta-llama/llama-3-3-70b-instruct"
```

---

### Error: Authentication failed / 401 Unauthorized

**Fix:** Check that your `WATSONX_API_KEY` is valid and not expired. Generate a new API key from [IBM Cloud IAM](https://cloud.ibm.com/iam/apikeys).

---

### Error: Project not found / 404

**Fix:** Verify your `WATSONX_PROJECT_ID` matches an existing project in your IBM watsonx.ai instance at the correct regional URL.

---

### Response is slow

IBM watsonx.ai inference for a 70B parameter model can take 5–15 seconds depending on prompt length and server load. The UI shows a spinner while waiting — this is expected behavior.

---

### CSV upload not working

Ensure your CSV:
- Has a **header row** as the first line
- Uses column names: `snr, ber, latency, throughput, packet_loss, rssi, jitter`
- Is plain UTF-8 encoded (not Excel `.xlsx` format)
- Is under ~1 MB in size

---

### UnicodeDecodeError on Windows

If you see encoding errors when running Python on Windows, ensure the file is saved with UTF-8 encoding. The `# -*- coding: utf-8 -*-` declaration at the top of `app.py` handles this.
